## 1. 设计标准

以 `ui-design-v1.png` 为主要视觉参考，首页、工具页、证件照流程、会员、电子照、个人中心和说明页使用统一的底色、卡片、字色及主要操作样式。页面需表达错误或禁用时，同时使用文字和颜色，不只靠颜色区分。

| 项目 | 标准 |
| --- | --- |
| 页面和卡片 | 浅灰页面底色 `#f6f6f6`，白色卡片，常规卡片圆角 24 rpx |
| 品牌与主操作 | 品牌红 `#cc3d35`；主要操作最小高度 96 rpx、圆角 20 rpx |
| 文字 | 主文字 `#17191c`；辅助文字 `#666b73`；说明文字需有足够行高 |
| 辅助色 | 蓝 `#356caa`、青 `#287c70`、紫 `#715a9b`、琥珀 `#956322`，配合浅色底用于图标、提示和功能分组 |
| 间距 | 常规水平边距约 28–32 rpx，卡片之间约 20 rpx；固定底部操作区预留安全区 |
| 导航 | 标准页面采用白色导航栏、黑色文字；相机和图片预览保留所需的深色对比 |
| 状态 | 加载、可用、异常、无法连接、未开放均有对应文案；会员购买未开放不显示为服务故障 |

公共颜色与组件样式见 `src/assets/design-tokens.scss`；旧工具页和说明页共享样式见 `src/assets/legacy-page-themes.scss`。后续新增页面应优先复用这些变量和 mixin，并在窄屏与长内容状态下检查固定按钮是否遮挡正文。

## 3. 服务状态的含义

首页显示服务状态条，“我的”提供详情入口。状态页显示服务连接、证件照默认模型、人像抠图默认模型、可选模型、图片工具、微信登录、会员数据库与会员购买状态。页面展示时每 60 秒刷新，也可手动重新检查；无法连接时提示检查网络或稍后重试。

后端 `GET /service-status` 无需登录，带 IP 限流和 `Cache-Control: no-store`。检查包括模型文件是否存在、会员数据库是否可只读访问，以及已监控接口近 5 分钟的服务端异常。某接口成功响应会清除该接口最近的异常记录；重启服务会清空内存中的近期异常。沙箱的状态接口明确说明没有接入图片处理。

这是运行状态摘要，并非实时端到端可用性保证：模型文件存在不代表实际推理一定成功；没有近期登录异常不代表微信登录服务一定可用；支付开启状态不代表第三方支付已验证；客户端无法连接时也无法判断究竟是手机网络、隧道还是服务器的问题。该功能不保存请求照片或个人身份信息作为状态记录。

## 4. 验证结果

### 构建与界面

- 微信小程序构建成功，输出目录为 `dist/ui-audit/mp-weixin`；构建过程中出现 npm 与 Node 版本兼容提示及 Browserslist 数据过期提示。
- 开发者工具逐页打开 23 个页面，并检查截图。交互验证覆盖首页搜索、自定义规格、服务状态与刷新、证件照编辑和排版选项、水印与人像抠图、历史记录按规格重新制作、会员三档价格与购买关闭状态。
- 模拟服务状态请求断开后，首页及详情页显示无法连接；恢复请求后，详情页手动刷新恢复正常。
- 格式转换页面验证了 PNG 选项、实际转换结果及保存回调；保存和激励广告使用模拟。水印输入验证了模拟输入事件到页面数据的绑定，以及提交水印文字后的后端处理。
- 普通用户广告、会员免广告、会员查询失败、广告未完整观看与加载失败等 8 个前端场景通过；服务状态解析及失败处理的 8 个场景通过；23 个页面通过导航样式和模板注释一致性检查。

### 后端

- 14 个隔离测试通过：状态接口、限流、故障与恢复、沙箱说明、会员自然月和续费叠加、退款标记、共享推理模型并发保护、图片处理和错误输入。
- 使用示例照片实际验证了证件照、人像抠图、换底、排版、水印、JPG/PNG 格式转换和图片大小处理。
- 在正在运行的本地正式服务上执行证件照推理时，3 次状态查询均返回 HTTP 200；该次推理约 8.61 秒，状态查询约 3–5 毫秒。
- 公网服务状态接口返回正常；本地健康检查返回 200，未登录的证件照接口返回 401。正式会员购买开关为关闭状态。

### 本次未覆盖

- 手机真实相机和相册授权、真实激励广告展示及保存到手机相册；开发者工具测试中的广告和保存回调使用模拟。
- iPhone 上的真实付款与退款通知链路；按当前要求没有开启正式收款，也没有发起真实交易。此前 Android 沙箱订单和续费已由用户在手机上确认成功，本次没有重复创建支付订单。
- 仅截屏和自动化检查不能覆盖所有手机尺寸、系统版本和所有故障组合；说明页、旧版入口和空状态主要进行了页面展示检查。
